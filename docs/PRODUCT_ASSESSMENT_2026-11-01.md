# Tab Out 产品价值与 To C 发布可行性评估

评估日期：2026-11-01。范围：当前 2.1.0 工作区，包括尚未提交的 Undo 与刷新修复。默认评估面向个人用户的 Chrome 扩展，不包含企业采购或特定国家的税务方案。

后续记录：本评估之后已实施 2.2.0 项目工作台，原窗口撤销、原生组权限等结论对应评估时的旧版本；当前实现及验证请见 [2.2.0 实现报告](ai-tasks/2026-11-01-project-workbench/implementation.md)。本文件保留为当时的产品决策依据。

## 1. 决策建议

**有使用价值，值得以小型独立产品继续验证；当前不宜作为成熟付费产品广泛推广。**

| 决策 | 判断 | 依据 |
| --- | --- | --- |
| 作为自用工具继续维护 | 值得 | 清理、保存、查找与恢复形成可用的基础能力组合 |
| 面向多项目个人用户发布测试版 | 有条件可行 | 先解决恢复保真和分发材料问题，再用真实使用验证需求 |
| 现在大规模公开收费 | 暂缓 | 核心恢复承诺有实现缺口；商业配置和条款未完成；缺少付费与留存证据 |
| 继续投入同步、团队或更多自动化 | 暂缓 | 这些功能尚不能解决获客、差异和信任这三个主要问题 |

这里的“可行”指值得做低成本验证，不代表已证明市场匹配、稳定收入或商店审核通过。

## 2. 哪些人会觉得它有价值

优先对象是同时处理多个项目、经常保留约 20–100 个标签页的个人用户：开发者、研究人员、设计师和产品经理。这个范围是建议招募条件，不是现有用户统计。

有价值的任务是：暂时收起一个项目，需要时快速回到相关网页；在大量标签中找回已有页面；误关后恢复最近的标签布局。

域名分组擅长回答“哪些网站开得太多”，但项目工作通常同时涉及代码、文档、设计稿和资料站。**更有付费潜力的是跨网站的项目整理与恢复，而不是把域名卡片画得更漂亮。**

建议验证的定位：**面向多项目个人用户、默认保存在本机的标签工作台。** 第一段产品演示只展示“保存当前项目 → 收起 → 找回并恢复”；再介绍搜索、规则和模板。

已有清理、撤销、工作区、搜索、备份和自动快照的代码基础。中英文、地址栏 `to` 搜索和可配置网站别名可以帮助切入开发者及中文知识工作场景，但是否足以促使用户迁移仍需实测。

## 3. 竞争位置：需求存在，差异尚弱

以下信息来自本次检索的官方页面；安装量和报价会变化。竞品自述的功能并未在本次逐项实际操作验证。

| 替代方案 | 已有能力或市场信号 | 对 Tab Out 的含义 |
| --- | --- | --- |
| Chrome 内置功能 | 原生标签组可关闭后再打开，开启相应同步后会保存和跨设备同步 | “保存一组标签”本身不构成充分购买理由。[官方帮助](https://support.google.com/chrome/answer/2391819?co=GENIE.Platform%3DDesktop&hl=en) |
| OneTab | 商店显示约 200 万用户；官网已有收纳、恢复、导入导出，以及文件夹、笔记和加密同步介绍 | 证明类别有需求，也意味着基础收纳很难形成壁垒。[商店](https://chromewebstore.google.com/detail/onetab/chphlpgkkbolifaimnlloiipkdnihall?hl=en)、[官网](https://www.one-tab.com/) |
| Session Buddy | 官方提供会话历史、崩溃恢复、项目集合、备份；强调本地存储和免登录 | “本地、免登录、恢复历史”也不是独占优势。[官网](https://sessionbuddy.com/) |
| Toby | 免费版最多保存 60 个标签；Productivity 为每月 US$6，或年付 US$54 | 说明市场中有付费供给，不证明 Tab Out 已有付费需求。[官方定价](https://www.gettoby.com/pricing) |

判断：当前更适合做有明确用户偏好的小众工具，而非依靠功能数量取胜的大众产品。低学习成本、恢复可信度和迁移便利性需要一起成立；只增加付费功能不能证明差异。

此外，新标签页是用户已有习惯的重要入口。当前 manifest 强制替换新标签页，应验证目标用户是否接受这一代价；不能把“经常出现”直接当成“经常产生价值”。

## 4. 发布准备度：具体阻断项

### 4.1 首要问题：恢复承诺超出当前实现保证

**代码事实一：原生标签组权限缺失。** [manifest](../extension/manifest.json) 没有声明 `tabGroups`；[Chrome 适配器](../extension/src/api/chrome-session-adapter.js) 依赖该 API 获取名称、颜色和折叠状态，不可用时直接返回空分组。官方明确列出该 API 所需的 `tabGroups` 权限。[API 文档](https://developer.chrome.com/docs/extensions/reference/api/tabGroups)

**代码事实二：合并恢复未保留源窗口和绝对位置。** `restoreSession(..., { mode: 'merge' })` 创建标签时未指定源窗口 ID 或原 index，虽然会对输入按 index 排序，但这不能保证回到原窗口和原位置；Undo 使用的正是此模式。见 [适配器](../extension/src/api/chrome-session-adapter.js) 和 [操作服务](../extension/src/services/operation-service.js)。

本次用内存 Chrome API 模型复查：输入两个窗口，各含一个标签和原生组；不提供 `tabGroups` API 时捕获到 0 个组；合并恢复的两次 `tabs.create` 均只有 URL 与 `active: false`，却报告成功恢复 2 个标签。这是代码路径验证，不是用户真实浏览器中的完整复现。

结论：发布前必须修复，或明确收窄“原样恢复窗口、顺序、原生组”的宣传，并在不满足承诺时显示具体结果。“重新打开两个 URL 成功”不能替代“项目布局恢复成功”。

### 4.2 免费测试与收费发布的门槛不同

| 优先级与适用范围 | 当前证据 | 需要完成的工作 |
| --- | --- | --- |
| 最高：所有对外测试 | 上述权限与恢复布局缺口 | 修复或收窄承诺；在干净浏览器配置中验证单页、分组、多窗口、部分失败和重启恢复 |
| 最高：普通用户安装 | README 仍以克隆、开发者模式和 AI 编程工具为入口，且指向上游仓库 | 提供本产品的商店安装入口、清楚的权限解释和首次保存恢复引导 |
| 最高：收费前 | [entitlement-config.js](../extension/entitlement-config.js) 中公钥、购买地址、兑换地址均为空 | 配置并验证购买、激活、离线使用、退款、撤销授权及升级更新；测试版若不收费，应明确说明 |
| 最高：公开发布前 | [隐私文档](PRIVACY.md) 的支持联系方式仍是占位文字；[条款](TERMS.md) 明确仍需补全销售主体等内容 | 发布可访问的正式隐私页面，补齐主体、支持方式与实际销售条款，核对所有数据流披露 |
| 次高：重度使用 | 本地快照有 8 MiB 上限，其他数据共享扩展存储配额 | 复验临近总配额、写入失败、导出与恢复，不把本机快照宣传成设备损坏后的备份 |
| 次高：转化与留存 | 事件保存在本机，无本次可用的真实留存、付费或获客数据 | 用自愿回访或明确同意的最小统计观察主动使用，不上传标题、URL、搜索词 |

Chrome 要求单一且清楚的用途、必要权限与准确的数据披露；本地存储也不能代替隐私说明。见[隐私申报说明](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)和[商店政策](https://developer.chrome.com/docs/webstore/program-policies/policies/)。

当前没有跨设备同步。浏览器本地数据会随扩展卸载被清除，默认 `storage.local` 配额为 10 MB；已有快照去重和容量限制能缓解问题，但不能提供设备外备份。[存储 API](https://developer.chrome.com/docs/extensions/reference/api/storage)

恢复范围也应写清：重新打开 URL 和支持的标签元数据，不等于恢复未提交表单、网页内存、任意登录状态或页面中未保存的内容。

## 5. 收费模式建议

先验证免费体验加个人 Pro 买断，US$19–29 可沿用为价格实验。这个区间来自仓库原有方案，是待验证假设，不是市场已接受的价格。没有独有持续服务价值之前，不建议优先做订阅。

免费体验应让用户完整走通保存、关闭、找回、恢复和导出。付费可围绕更多项目、规则自动化、长期历史管理等持续需求，避免在用户焦急找回误关页面时制造突然的付费阻断。当前 Free 可访问最近 3 个自动快照，需专门观察用户对这个边界的理解与信任。

持续维护和支持是买断模式的真实成本。例如，每 1,000 名试用者若有 3% 以 US$19 购买，只有 US$570 毛收入，尚未扣支付费、税费、退款、获客和支持成本。这只是算术情景，不是转化率预测，也不是月收入预测。

仓库采用 MIT 许可，许可允许在保留相应版权和许可声明的条件下销售软件；仍应单独核对产品名称、商店素材和发布者身份。开源收费的理由应是可靠维护、便利和支持，而不是依赖功能无法被复制。[仓库许可](../LICENSE)、[MIT 许可原文](https://opensource.org/license/mit)

## 6. 建议的验证顺序

1. **先兑现恢复承诺。** 冻结增加功能，处理权限与窗口布局，形成干净配置下的可重复浏览器测试记录。基础门槛：支持范围内无静默遗漏；失败可见、可解释；导出与导入结果一致。
2. **小范围分发。** 补齐必要发布材料后，用商店 Unlisted 或 Private 向约 30 位目标个人用户开放，避免让开发者模式的安装难度污染需求判断。官方支持这两种分发方式，但仍须走商店流程。[分发设置](https://developer.chrome.com/docs/webstore/cws-dashboard-distribution)
3. **观察两周主动使用。** 首次使用要求用户不依赖作者指导完成一次保存、关闭和恢复。记录任务成功和困惑点；以主动保存、恢复、搜索衡量使用，不以被动打开新标签页当作活跃。
4. **验证真实购买。** 对有重复使用的用户提供清楚、可交付的 Pro 方案，观察真实付款；“觉得不错”或登记邮箱只算弱信号。付款前完成商业配置和正式销售说明。

可事先约定一个简单继续投入门槛：30 人中至少 18 人独立完成首次核心任务，至少 10 人在第二周的两个不同日期主动使用核心功能，至少 3 人实际付费。这些是建议的实验决策线，不是行业标准；小样本结果也不能外推市场转化率。

如果复用率不足，先定位是否目标任务不够频繁、操作比现有工具更麻烦，或替换新标签页的代价过高。若有人持续用但无人购买，重新检查付费价值，而不是立即增加同步或 AI。
