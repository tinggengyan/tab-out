## 整体审查（2026-11-12，独立审查员，上下文全新）

结论：没有严重问题。按对实际使用的影响重新定级后，分两类处理。

**已修复**（`cf40114`）。每项都先写失败的测试，再修复：

| 问题 | 原定级 → 重定级 | 测试 |
|---|---|---|
| 点面板里的非输入区域（如"esc"标记）后焦点跑到页面上，esc、方向键、回车全部失灵 | 重要 | 场景 16 `a click inside the panel keeps the keyboard in the box` |
| 中文输入法打拼音期间按拼音实时搜索，"没有找到"闪烁 | 次要 → 重要（负责人日常用中文输入） | `pinyin being composed is not searched` |
| 输入法选字时按 esc 会关掉整个浮层 | 次要 → 重要（同上） | `esc while composing leaves the overlay open` |

**补上的测试缺口：**
- 比最近 3000 条更早的访问，要靠 Chrome 自带的历史搜索才能找到。原来没有测试覆盖这条路径，现在已授权套件先写入 3000 条更新的访问再验证。
- 浮层打开后收纳记录被改动：场景 16 在回车前往记录最前面插入一页，检查只移出找到的那一页。
- 只读约束从只检查 `app.js` 扩到扩展的全部脚本。

## Claude 的决定（实施中）

- **Task 2 和 3 合并为一次提交。** 静态契约要求 `app.js` 里只有一处权限申请，这条测试要等浮层代码写好才能通过。分开提交会留下一个测试不通过的中间提交。代价：提交粒度略粗。
- **已授权场景用"权限补全的扩展副本"测试，不点真实授权弹窗。** headless Chrome 没法点扩展的权限弹窗。代价：真实弹窗，以及授权后无需刷新就能用书签、历史接口，这两点没有自动化覆盖，见下文"需要人工验收"。
- **历史记录同时用两种方式取。** 一是浮层打开时取最近 3000 条，在本地按子串匹配；二是每次输入再调用 Chrome 自带的历史搜索补上更早的记录。合并后统一用本地规则过滤。原因是 Chrome 自带搜索按词匹配，对中文子串的匹配效果未验证。代价：每次打开浮层多读一次历史。
- **规避中文输入法冲突。** 输入法正在选字时，回车和方向键交给输入法，不触发结果（`isComposing` / keyCode 229）。
- 其余决定（"本窗口 / 其他窗口"、组名用"已收纳"、收纳单页在前台打开、3000 条）见 [design.md](./design.md) §8。

## 已知限制

- 新开标签页时焦点在地址栏，要先点一下页面，`/` 才生效。这是 Chrome 的限制，所以保留了按钮。
- 一个标签页都没开时，"打开的标签页"整块隐藏，按钮也跟着隐藏，只能按 `/`。
- 浮层打开期间，在别的窗口开关的标签页不会实时更新到搜索结果里；关掉浮层再打开即可。

## 需要人工验收

在自己的 Chrome 里加载 `extension/`，然后检查：

1. 点"搜索"，输入一个词，确认三组结果，以及回车后的行为。
2. 点"开启"，确认 Chrome 弹出授权框，并记下实际措辞。点"允许"后，不刷新页面，书签和历史两组应立即出现。
3. 在 `chrome://extensions` → Tab Out → 详情里撤销这两项权限，再打开搜索，"开启"卡片应重新出现。
4. 用中文输入法输入，确认选字时按回车不会误打开结果。
