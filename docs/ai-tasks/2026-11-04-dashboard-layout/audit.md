# 首页信息层级审视

依据：用户2026-11-04提供的[首屏截图](evidence/01-before-home.png)与[滚动后截图](evidence/02-before-scrolled.png)，均已实际查看。范围为Tab Out首页布局，不将静态截图当作完整功能或无障碍验收。

用户的主要目标是打开新标签页后直接查看、切换、收纳当前标签及恢复已有分组。当前视觉沿用暖色系统、文字与控件分组清楚，但新增功能改变了使用顺序。

| 步骤 | 状态 | 截图证据与影响 |
| --- | --- | --- |
| 1. 打开首页 | 不符合主任务 | 首屏最上方是整块浏览记忆：大标题、介绍、筛选、正文发送许可、隐私说明、统计、空状态和设置入口。即使没有执行搜索，这些内容仍占据大块空间。 |
| 2. 找到当前标签 | 需要多余滚动 | 浏览记忆下方又叠加项目标题、说明、空列表和备份说明。用户截图的当前标签仅在首屏底端露出标题，滚动后才能操作卡片。问题同时来自两个大区。 |
| 3. 进入搜索或项目 | 功能入口明确，层级过重 | 新功能可发现，但把偶尔需要的完整界面放在每次打开首页的必经路径，降低高频标签管理效率。未搜索却出现引导记录的空态，与已有28条记录的状态也不相称。 |

建议：保留现有视觉与功能节点，顶栏设置“标签页／项目／浏览记忆”三个紧凑入口，默认显示标签页。项目和搜索各自按需显示，在原有面板完成操作；说明、设置及空状态仅存在于所属视图。切换保持查询、结果和列表，不改数据结构。以桌面首张标签卡的位置、已收纳首项是否在首屏、窄屏实际布局及键盘返回行为验证。

截图无法证明焦点顺序、键盘操作、屏幕阅读器行为或完整色彩对比符合标准；后续只对本次改动的导航、焦点、模态层及真实Chrome交互作具体检查，不声称全面无障碍合规。
