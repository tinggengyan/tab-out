## 1. 意图

负责人原话：

> 这个项目的灵魂是：按照域名为维度即以站点为维度进行聚合展示，可以一键关闭、关闭重复、收纳。
> 项目的现状已经面目全非，失去了灵魂，走向了歪路。
> 你看这个页面和布局，已经太丑了。

审视结论（详见报告）：

- 三个灵魂动作在首页被降级或拆掉了：
  - 关闭本站：从 1 次点击变成 2 次，按钮藏进"更多"。
  - 收纳本站：从 1 次变成 5 次加 2 层弹窗。
  - 找回收纳：从首页右栏 1 次点击，变成要切换视图、约 3–4 次。
- 首页被每行的 ✓、说明文字、三视图导航和 6 个底栏入口占满。
- 走偏的原因：商业化转向"浏览工作台"，叠加高速的 AI 多角色开发；每轮验收从没检查过"首页还像不像 Tab Out"。

负责人确认：产品未对外发布，唯一的老用户是他本人。因此不再背"老用户兼容"的包袱。决定**以 `40579ec` 的 `extension/` 为底重建**，只移植少量确有价值的改进。其余功能留在归档标签里。

## 2. 目标、非目标、反目标

### 目标

1. 新标签页打开即见：当前所有标签页按站点归成卡片。"常用首页"（Gmail、X、YouTube 等）单独一组，localhost 显示端口。
2. 每张卡片都能 **1 次点击**完成以下动作，按钮常驻可见，不进任何菜单：
   - 关闭本站全部
   - 收纳本站
   - 关闭本站重复（只在有重复时出现）
3. 区头全局动作，各 1 次点击：
   - 关闭全部重复（只在有重复时出现）
   - 全部收纳
   - 关闭全部

   **作用范围：所有窗口**（负责人 2026-11-11 决定，与原版一致）。卡片级的"关闭本站""收纳本站"同样跨窗口。"全部收纳"生成 1 条记录。撤销时，页面回到各自原来的窗口；原窗口已关闭的，新开一个窗口放回。"全部恢复"在当前窗口打开。
4. 首页右栏：
   - **已收纳**：收纳记录列表。"全部恢复"1 次点击，也能单页恢复和删除。
   - **稍后查看**：单页待读清单，带归档。
5. 所有关闭类动作都可撤销：单页关闭、本站关闭、去重、全部关闭、收纳。
6. 页面不发出任何外部网络请求。

### 非目标（本次不做，留在归档里）

项目 / 已保存视图、快照与历史现场、回收站、统一搜索 ⌘K 与网站别名搜索、omnibox、键盘快捷命令、浏览记忆与 AI、规则与模板、清理建议、付费授权与 license 服务端、遥测、首次引导、按窗口视图、跨站点多选保存、繁体中文与日文、`server/`。

### 反目标（出现以下任一情况，即使功能能用也算失败）

- 首页出现需要用一段话解释的说明文字。
- 卡片里的按钮比标签页行更显眼，或者卡片级按钮折成多行、竖排。
- 任何灵魂动作需要先展开菜单或经过确认弹窗。"关闭全部"首次使用可以有一次轻提示，见 §4.4。
- 点击一个按钮导致不相关的元素跳动或位移。
- 页面向 Google 或任何第三方发请求（图标、字体都不行）。

## 3. 约束

- 纯 Chrome MV3 扩展，原生 JS/CSS/HTML，无框架、无构建、无运行时依赖。Node 只用于测试和工具。
- 保留 manifest 里的 `key`。它决定扩展 ID 不变，负责人现有的 `chrome.storage.local` 数据因此在重载后仍然可读。
- 权限只保留 `tabs`、`storage`、`favicon`。去掉 `activeTab`、`tabGroups`、`alarms`、host 权限和全部可选权限。
- 界面语言：English、简体中文（与原版一致）。四种语言并存的机制不保留。
- 卡片 CSS 视觉沿用原版的纸色 / 墨色 / 琥珀色体系。
- `npm test` 与 `npm run check` 必须通过，并保留真实浏览器测试运行器。

### 4.3 卡片结构

```
┌ GitHub   5   1 个重复 ───────────────────┐ ← 标题、数量、重复徽标同一行，不折行
│ ▣ tinggengyan/tab-out         (2x)       │

└──────────────────────────────────────────┘
```

- 每行只有两个操作：稍后查看（书签图标）、关闭。没有勾选框。
- 卡片按钮在任何支持的宽度下都保持单行。宽度不够时，改用短文案（"关闭 5""收纳""去重 1"），完整文案放进 `title` 和 `aria-label`。
- 去重按钮用琥珀色描边，不能看起来像禁用状态。
- 超过 8 个标签时沿用原版的"+N 更多"展开。
- 一并修掉原版的两个问题：
  - 卡片按钮折成两行（"关闭全部 5 / 个标签页"）。
  - 重复徽标单独占一行。

### 4.4 撤销

- 范围：单页关闭、本站关闭、去重（卡片级和全局）、全部关闭、收纳（本站和全部）。
- 关闭前记录每个被关标签的 `url`、`windowId`、`index`、`pinned`。固定页本来就不会被关闭。
- 撤销的行为：
  - 原窗口还在：在原窗口按原位置重新打开。
  - 原窗口已关：新开一个窗口打开。
  - 对收纳的撤销：重新打开页面，并删除刚产生的那条收纳记录。
- 只保留最近一次操作。toast 上显示"撤销"，30 秒后或下一次操作发生时失效。
- 实现为一个可在 Node 中单测的小模块，沿用"IIFE + `module.exports`"写法。
- "关闭全部"只在**第一次**使用时出现一次确认提示，之后靠撤销兜底。

### 4.5 收纳语义（OneTab 式）

- **收纳**：把一组标签页存成一条收纳记录，并关闭这些页。
  - 存储在**新键 `collectedGroupsV3`**，格式为 `{ id, savedAt, name?, sourceId?, tabs: [{ url, title }] }`。
  - 不复用 `tabGroups` 键。原因：归档版 v2.3 每次读取项目都会把 `tabGroups` 吸收进 `workspacesV2` 并清空它（`project-normalization.js:33-66`）。用新键后，即使以后在同一个 Chrome 配置里临时加载归档版，v3 的收纳记录也不受影响。
  - 原版导出文件里的 `tabGroups`，在导入时转换为这个新键。
- **全部恢复**：在当前窗口重新打开整组，然后**删除这条记录**。
- **单页恢复**：打开该页，并从记录中移除它；记录空了就整条删除。
- 没有"锁定"功能。负责人决定以后需要时再加。

### 4.6 负责人现有数据（一次性、自动、不删除）

扩展 ID 不变，所以 `chrome.storage.local` 里的旧键仍在。新版首次启动时：

1. 若 `soulMigrationV1` 未设置，读取 `workspacesV2`，以及 `tabGroups` 中可能残留的旧记录，把每一条转成收纳记录追加到 `collectedGroupsV3`：
   - `name` ← 项目名；
   - `savedAt` ← 项目的保存或创建时间；
   - `tabs` ← `entries` 的 `url` 与 `title`；
   - `sourceId` ← 原记录 ID。

   然后写入 `soulMigrationV1 = { migratedAt, count }`。迁移按 `sourceId` 去重，即使被重复执行也不会产生重复记录。
2. `deferred`、`shortcuts` 的格式与原版兼容，直接沿用。
3. **不删除任何旧键**，包括 `workspacesV2`、快照，以及浏览记忆的 IndexedDB。新版代码只是不再读取它们。
4. 导入功能同时接受原版格式（`version: 1`）和 v2.3 的备份格式（`version: 2`，取 `data.shortcuts`、`data.deferred`、`data.workspacesV2`），作为兜底。

| # | 标准 | 检查方式 |
|---|---|---|
| 1 | 第一张卡片顶部 ≤ 100px | 真实浏览器测试 |
| 2 | 首屏常驻可见的交互控件 ≤ 30 个（悬停才出现的行内按钮不计） | 真实浏览器测试 |
| 3 | 每张卡片的按钮同处一行（各按钮 `top` 相同），1440 与 1366 宽度、两种语言都成立 | 真实浏览器测试 |
