# 保存入口职责与范围收敛

Forge L1：已有保存流程不变，仅收敛入口、文案与层级。来源：用户询问多处“保存为项目”如何修复；此前已讨论标签页负责当前网页、项目负责保存内容管理。

## 冻结方案

- 标签页顶部保留主保存入口“保存为项目”与“保存并收起”，保留上一轮两级按钮样式。
- 项目页只保留一个次级入口“从当前标签页创建项目”（新四语key），移除该页重复的“保存并收起”按钮；仍用同一个安全选择/预览对话框，里面保留两种保存方式。
- 标签页卡片的保存按钮明确“保存本组到项目”；所选按钮保留清楚的“保存所选到项目”。避免同名全局动作重复出现，不新增复杂菜单、隐藏状态或存储类型。
- 四语言同步；保持按钮IDs中projectSaveBtn作为现有保存入口、所有tab IDs/actions与保存/关闭/恢复规则不变。projectParkBtn实际DOM与localize/绑定一并移除，不以隐藏死按钮冒充清理。controller.begin('park')仍从标签页入口可用。

## 通过条件

1. 项目页header只有次级“从当前标签页创建项目”，不再出现两个同名主要保存按钮；标签页全局保存主入口保留。
2. 域名/窗口卡片的本组及所选范围文案明确，实际tab ID预选范围保持；同一预览可新建/更新、仅保存/收起，无新业务分支。
3. 项目次级入口、标签页保存/收起及卡片本组/所选均可打开预览，取消不写项目/不关页；焦点返回真实可见按钮，没有对缺失projectParkBtn访问。
4. 四语key/placeholder一致，1440/1366/390下无溢出；固定底栏、上一轮快捷按钮两级样式保留。
5. 相关Node及真实隔离Chrome入口/语言/项目回归通过；只改必要UI/文案/合同测试，不改业务服务/存储/权限/模型模块/AGENTS/CLAUDE，不操作个人Chrome或提交发布。10个旧ZIP不覆盖，另生成新试用包。
